\section{Introduction}

The key-value (KV) cache used to set the operating point of long-context inference, and prior systems work optimized around it through offloading and quantization \cite{bocharnikov_kv_2026}. The 2026 generation of edge-scale instruct models breaks that constraint at the architecture level. Gated Delta Networks replace the growing KV cache with a fixed-size recurrent state and turn attention into a linear-time operation \cite{yang_gated_2025,sun_fg2-gdn_2026}; in deployment, that state stays small enough to remain on chip across decode steps \cite{gupta_persistent-state_2026}. Recent benchmarks across Phi-4, Gemma 4, and Qwen 3 confirm the shift: peak GPU memory and per-token FLOPs are the operating-point metrics that matter now, rather than raw cache size \cite{manik_gemma_2026}, and grouped-query attention closes the same gap on the dense side \cite{ainslie_gqa_2023}. We measured per-token KV growth across these three architectural classes on a single $5{,}000$-token greedy decode and found exactly this stratification: Qwen 3.6's hybrid Gated-DeltaNet stack grew at $27$ KB/tok (near-flat), Phi-4-mini's dense GQA at $128$ KB/tok, and Gemma 4's sliding-window MoE at $221$ KB/tok (Figure~\ref{fig:phase1_4_kv_growth}).\footnote{Gemma's slope is the steepest of the three because the sliding window bounds compute, but the reference \texttt{DynamicCache} retains entries past the window, so memory grows unimpeded.} The cost ledger has therefore moved off the cache. What dominates instead is the cognitive cost: tokens spent extending an already-wrong reasoning trajectory \cite{chen_think_2026,wu_when_2025,fu_multiple_2026}, an effect that scales with chain-of-thought length and accounts for a growing share of inference cost on reasoning models \cite{zhang_100_2025}. Those wasted tokens often arrive packaged as fluent but hallucinated answers, with errors propagating along the trajectory rather than surfacing at the output \cite{zhang_harnessing_2026}.

% GAP: Existing RAG triggers are structurally late.
% - GRIP: emits a trained <retrieve> token — must wait for full decode step.
% - ReaLM-Retrieve: step-level uncertainty from verbalized confidence +
%   entity-coverage entropy — parses generated text post-hoc.
% - Both are post-decode: the model has already committed tokens before
%   the trigger fires. On instruct-tuned 2026 models, ReaLM's hesitation
%   regex fires on step 1 of nearly every trace (protocol-fragile).

Active retrieval triggers fall into two structural patterns. The first internalizes retrieval as part of the generation vocabulary: Self-RAG and Open-RAG train the model to emit reflection tokens such as \texttt{[Retrieve]} \cite{Asai_SelfRAGLearning,Islam_OpenRAGEnhanced}, and GRIP extends the idea with explicit control tokens that schedule retrieval inside the autoregressive trajectory \cite{Li_RetrievalGenerationUnified}. The second parses the generated text after each reasoning step: FLARE evaluates token probabilities of a provisional next sentence \cite{Jiang_ActiveRetrievalAugmented}, DRAGIN evaluates the uncertainty and semantic importance of each generated token \cite{Su_DRAGINDynamicRetrieval}, and ReaLM-Retrieve combines a verbalized $0$-$100$ confidence rating with named-entity entropy at step boundaries \cite{Guo_WhenRetrieveAdaptive}.% NOTE for self: ReaLM-Retrieve's full RSUS also includes a third consistency component U_cons; omitted here for brevity, mention in §5 if space allows.
 Both families pay the same structural delay: by the time the trigger evaluates, the model has already sampled the tokens it is meant to assess, and recent work names this as the delayed-retrieval problem in dynamic RAG \cite{Li_ModelingUncertaintyTrends}. Latent-space alternatives exist (LatentRAG, LAnR), and they bypass discrete decoding by routing through a learned latent code, but they require an additional projection head trained against a retrieval objective \cite{Zheng_LatentRAGLatent,T_LatentAbstractionRetrieval}. We instead probe the forward pass the model already runs: hidden states at sentence boundaries are observable on every architecture without an extra training stage, and single-pass hidden-state probes recover semantic uncertainty before a token is sampled \cite{Kossen_SemanticEntropyProbes,Chen_INSIDELLMsInternal}.

\section{Methodology: Geometry-Aware Latent Gating}

% 3.1 THE CRV ADAPTER
% - Use output_hidden_states=True (public API, no hooks, arch-agnostic).
% - At each logical step boundary (sentence-end detector), mean-pool
%   per-token hidden states from layer floor(L/2) → CRV_t.
% - Cosine drift: d_t = 1 - cos(CRV_t, CRV_{t-1})
% - Rolling L2 variance: v_t = Var(||CRV_{t-w}||, ..., ||CRV_t||)
% - Gate fires if d_t > tau_d (mode=drift), v_t > tau_v (mode=variance),
%   or either (mode=or).
% - Overhead: ≤3% throughput at steady state on 5,000-token traces.

% 3.2 THE L1 LANDMINE
% - On MoE models, the router selects different experts per token.
%   At the last layer, expert-switching noise dominates the hidden state.
% - Qwen3.6 last-layer mean drift: 0.479 (near-saturated cosine distance).
% - Qwen3.6 mid-stack mean drift: 0.235 (clean, separable signal).
% - Mid-stack (pre-routing) bypasses the noise entirely.
% - Verified on all three architectures: Phi (dense, no L1),
%   Gemma (MoE, mild L1), Qwen (hybrid MoE, severe L1).

% 3.3 GEOMETRY-AWARE CALIBRATION PROTOCOL
% - On the calibration split ONLY (120 q, pre-partitioned, SHA-pinned):
%   1. Fit per-gate thresholds to hit 30% per-step fire rate (iso-fire-rate).
%   2. Compute Δfrac under each of {drift, variance, or}.
%   3. Pick the mode with the highest calibration Δfrac.
% - Freeze mode + thresholds. Evaluate on validation (40 q).
% - Result: Phi → variance, Gemma → or, Qwen → or.
% - The mid-stack adapter is universal; the heuristic is geometry-dependent.
% - Zero validation leakage by construction (L5 contract in _PLAN.md).
